# العمر البيولوجي

موقع عربي (RTL) متجاوب مع الجوال والحاسوب. يُدخل الموظف بياناته ونتيجتي اختبار اللياقة، فيحصل على **تقدير حسابي** لعمره البيولوجي وتصنيف كل اختبار وتوصيات عامة للنشاط البدني. تُحفظ السجلات في قاعدة بيانات خلفية، ولا يطّلع عليها إلا حسابات الإدارة المخولة.

> النتيجة تقدير حسابي وفق معادلة الموقع، وليست تشخيصًا طبيًا.

## التشغيل

المتطلبات: Node.js بإصدار 22.13 أو أحدث (يستخدم SQLite المدمج في Node، فلا حاجة إلى خادم قاعدة بيانات منفصل).

```bash
npm install
npm run create-admin -- admin admin "مدير النظام"
npm start
```

- صفحة الموظف: `http://localhost:3000/`
- لوحة الإدارة: `http://localhost:3000/admin`

### الشعارات
شعار BAE Systems (`public/assets/logos/bae-systems.png`) في يمين الترويسة، وشعار عيادات حياتنا (`public/assets/logos/hayatna.png`) في يسارها. يبقى موضعا الشعارين ثابتين في اللغتين. لاستبدال أي شعار ضع ملفًا جديدًا بالاسم نفسه.

### اللغات (العربية ⇄ الإنجليزية)
زر الترجمة في الترويسة يبدّل الموقع كاملًا بين العربية (RTL) والإنجليزية (LTR): صفحة الإدخال والنتيجة ولوحة الإدارة.
- يتذكر المتصفح اللغة المختارة في جميع الصفحات.
- يرسل المتصفح اللغة إلى الخادم (الترويسة `X-Lang`)، فتصل رسائل الأخطاء والتصنيفات والتوصيات وملفات CSV باللغة نفسها.
- نصوص الواجهة في `public/js/i18n.js`، ورسائل الخادم في `src/i18n.js`، والتسميات الإنجليزية للتصنيفات في العمود `label_en` من جدول `scoring_rules`.
- تحفظ السجلات رمز التصنيف، فيُعرض السجل نفسه بأي لغة.

## الصفحات

| المسار | الوصف |
|---|---|
| `/` | إدخال البيانات: المعلومات الأساسية ونتائج الاختبارين، مع التحقق من القيم |
| `/result#<رمز>` | النتيجة: الاسم والجنس والعمر الزمني، والعمر التقديري، والفارق، والتصنيفات، والتوصيات |
| `/admin` | لوحة الإدارة بأقسامها: التقارير، والسجلات، والحسابات، وسجل التدقيق، وحسابي |

يُوضع رمز النتيجة بعد علامة `#` في الرابط، فلا يُرسل إلى سجلات الخادم. صلاحية الرابط 24 ساعة افتراضيًا.

## الحساب

- جداول التصنيف محفوظة في جدول `scoring_rules` داخل قاعدة البيانات، وتُزرع عند أول تشغيل من `src/db.js`.
- التصنيف والحساب يتمان في الخادم فقط. لا تُرسل الجداول ولا النقاط إلى واجهة الموظف، بل يتلقى التصنيف والنتيجة فقط.
- **مجموع النقاط** = نقاط اختبار الخطوة + نقاط PBF
- **العمر التقديري** = العمر الزمني + مجموع النقاط
- **الفارق** = العمر التقديري − العمر الزمني
- إذا كانت PBF أقل من 10% (أو كانت أي قيمة خارج نطاق التصنيف)، لا يُحسب العمر ولا يُحفظ السجل، ويُطلب تصحيح القيمة.

## الصلاحيات

| الدور | الصلاحيات |
|---|---|
| `admin` | التقارير المجمعة، والسجلات الفردية والبحث فيها، وحذف السجلات، وتصدير السجلات مع الاسم ورقم التواصل |
| `analyst` | التقارير المجمعة والتصدير الإحصائي فقط، دون أي بيانات شخصية |

```bash
npm run create-admin -- analyst1 analyst "محلل البيانات"
```

- **الحسابات:** ينشئ المدير الحسابات من قسم «الحسابات» في اللوحة، ويغيّر أدوارها ويعطّلها ويعيد تعيين كلمات مرورها. تعطيل الحساب أو تغيير صلاحيته ينهي جلساته فورًا. ولا يمكن للمدير تعطيل حسابه أو خفض صلاحيته بنفسه، ويبقى دائمًا حساب مدير نشط واحد على الأقل.
- **حسابي:** يغيّر كل مستخدم كلمة مروره بنفسه (12 حرفًا على الأقل)، فتنتهي جلساته على الأجهزة الأخرى.
- **الحذف:** يحذف المدير سجلًا واحدًا، أو كل السجلات المنشأة قبل تاريخ محدد. ويحذف الخادم تلقائيًا السجلات الأقدم من `RETENTION_DAYS` إن ضُبطت.
- **سجل التدقيق:** يُعرض في اللوحة، ويسجّل: الدخول، ومحاولات الدخول الفاشلة، والاطلاع على السجلات، والتصدير، والحذف، وتعديل الحسابات.

## الإعدادات (متغيرات البيئة)

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `PORT` | `3000` | منفذ الخادم |
| `DB_FILE` | `data/biological-age.db` | مسار ملف قاعدة البيانات |
| `NODE_ENV` | — | اضبطه على `production` في بيئة التشغيل (يُفعّل ملفات تعريف الارتباط الآمنة) |
| `TRUST_PROXY` | `false` | اضبطه على `true` خلف Nginx أو موازن أحمال |
| `COOKIE_SECURE` | حسب `NODE_ENV` | ملفات تعريف ارتباط HTTPS فقط |
| `SESSION_IDLE_MINUTES` | `120` | مدة خمول جلسة الإدارة |
| `RESULT_LINK_HOURS` | `24` | صلاحية رابط النتيجة للموظف |
| `RETENTION_DAYS` | `0` | الحذف التلقائي للسجلات الأقدم من هذه المدة (0 = معطّل) |
| `SUBMIT_RATE_LIMIT` | `120` | الحد الأقصى لعمليات الإرسال لكل عنوان IP خلال 10 دقائق |

## قبل الإطلاق (حماية البيانات)

البيانات الصحية بيانات حساسة وفق نظام حماية البيانات الشخصية السعودي. قبل التشغيل يجب على الجهة:

1. تحديد مدة الاحتفاظ وضبط `RETENTION_DAYS`.
2. تحديد من يملك دور `admin` ومن يملك دور `analyst`.
3. التشغيل عبر HTTPS فقط مع `NODE_ENV=production`.
4. تأمين ملف قاعدة البيانات ونسخه الاحتياطية (صلاحيات الملفات وتشفير القرص).
5. مراجعة نص الإشعار في صفحة الإدخال وإضافة رابط سياسة الخصوصية الخاصة بالجهة.

## النشر

### Render (الطريقة الأسهل)
1. ارفع المشروع إلى مستودع على GitHub.
2. في Render اختر: **New ← Blueprint**، ثم المستودع. سيقرأ Render ملف `render.yaml` تلقائيًا.
3. أدخل قيمة `ADMIN_PASSWORD` (12 حرفًا على الأقل) عندما يطلبها، ثم اضغط **Apply**.
4. بعد اكتمال النشر يظهر رابط مثل `https://biological-age.onrender.com`. لوحة الإدارة على `/admin`، واسم المستخدم `admin`.

الخطة المحددة `starter` مدفوعة، وهي لازمة للقرص الدائم الذي يحفظ قاعدة البيانات؛ فالخطة المجانية تحذف البيانات عند كل إعادة تشغيل. يُنشأ حساب المدير الأول تلقائيًا عند أول تشغيل فقط، ويُدار بعدها من قسم «الحسابات» في اللوحة. لربط نطاق خاص بالجهة: Settings ← Custom Domains.

### Docker
```bash
cp .env.example .env
docker compose up -d --build
docker compose exec app node --disable-warning=ExperimentalWarning scripts/create-admin.js admin admin "مدير النظام"
```
تُحفظ قاعدة البيانات في وحدة التخزين `app-data`، ويُنشر التطبيق على المنفذ المحلي 3000 فقط.

### Nginx وHTTPS
يحتوي الملف `deploy/nginx.conf` على مثال جاهز: تحويل HTTP إلى HTTPS، وتمرير الطلبات للتطبيق، وقسم اختياري لقصر لوحة الإدارة على شبكة الجهة. اضبط `TRUST_PROXY=true` عند التشغيل خلفه.

### النسخ الاحتياطي
```bash
npm run backup -- /path/to/backups
```
ينشئ نسخة متسقة أثناء التشغيل، ويحتفظ بآخر 14 نسخة (يمكن تغييرها بالمتغير `BACKUP_KEEP`). يُنصح بجدولته يوميًا عبر cron وتخزين النسخ في موقع مشفّر.

فحص سلامة الخدمة متاح على `GET /healthz`.
